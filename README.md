# eubl.org

Source of the website of the **European Bioinformatics League** (EUBL), <https://eubl.org/>.

The site is generated by [Hugo](https://gohugo.io/) from Markdown and YAML files and published to GitHub Pages by GitHub Actions on every push to `main`. It uses no CSS or JavaScript framework, sets no cookies, and loads nothing from third-party servers.

## Where things are

| To change…                                   | edit                                         |
|----------------------------------------------|----------------------------------------------|
| Page text                                    | `content/*.md` (Markdown)                    |
| Dates of the current edition                 | `data/editions/2027/schedule.yaml`           |
| Committee members                            | `data/editions/2027/committees.yaml`         |
| Results                                      | `data/editions/2027/results.yaml`            |
| Organising institutions and sponsors         | `data/editions/2027/partners.yaml` + `data/institutions.yaml` + logo in `static/logos/` |
| Registration link, contact e-mail, menu      | `hugo.toml`                                  |
| Appearance                                   | `assets/css/main.css` (the only stylesheet)  |
| Page structure                               | `layouts/` (Hugo templates)                  |

Every YAML file starts with a comment explaining its fields. For most updates during a competition, only the files in `data/` need to be touched.

### Shortcodes available in Markdown

| Shortcode            | renders                                                  |
|----------------------|----------------------------------------------------------|
| `{{< schedule >}}`   | the timeline of the current (or given) edition           |
| `{{< results >}}`    | results tables of each published round                   |
| `{{< committees >}}` | organising and scientific committees                     |
| `{{< partners >}}`   | organising institutions and sponsors                     |
| `{{< notice >}}…{{< /notice >}}` | a highlighted note                           |

Each accepts `edition="2028"` to show another edition; inside `content/editions/<year>/index.md` the edition is taken from the page's front matter.

### Front matter options for pages

```yaml
title: Rules
description: One sentence for search engines and link previews.
lede: An introductory paragraph shown under the title.
status: draft              # shows a "Draft" notice at the top of the page
statusNote: Custom text for that notice.
toc: true                  # shows a table of contents
```

## Starting a new edition

1. Copy `data/editions/2027/` to `data/editions/2028/` and empty or update the files.
2. Copy `content/editions/2027/` to `content/editions/2028/` and set `edition: "2028"` in its front matter.
3. Set `currentEdition = "2028"` in `hugo.toml`.

The 2027 page stays online unchanged, with its results.

## Working locally

Install Hugo **extended**, version 0.167 or later (`brew install hugo`, `sudo apt install hugo`, `winget install Hugo.Hugo.Extended`, or a binary from the [releases page](https://github.com/gohugoio/hugo/releases)). Then, from the repository root:

```sh
hugo server          # live preview at http://localhost:1313/
hugo                 # full build into public/
```

Typical change workflow: edit, check in `hugo server`, commit, push. The site is live about a minute after the push; progress is visible under the repository's **Actions** tab.

## First-time setup on GitHub

1. Create the repository (e.g. `eubl/eubl.github.io` in a `eubl` organisation) and push this directory to its `main` branch.
2. **Settings → Pages → Build and deployment → Source:** select **GitHub Actions**.
3. **Settings → Pages → Custom domain:** enter `eubl.org`, save, and once the certificate is issued tick **Enforce HTTPS**.
4. At the registrar of `eubl.org`, create these DNS records:

   | Type  | Name  | Value                   |
   |-------|-------|-------------------------|
   | A     | @     | 185.199.108.153         |
   | A     | @     | 185.199.109.153         |
   | A     | @     | 185.199.110.153         |
   | A     | @     | 185.199.111.153         |
   | AAAA  | @     | 2606:50c0:8000::153     |
   | AAAA  | @     | 2606:50c0:8001::153     |
   | AAAA  | @     | 2606:50c0:8002::153     |
   | AAAA  | @     | 2606:50c0:8003::153     |
   | CNAME | www   | `<organisation>.github.io` |

5. Recommended: verify `eubl.org` for the organisation (**Organisation settings → Pages → Add a domain**), which prevents anyone else from claiming the domain on GitHub Pages.
6. Add committee members as collaborators (or as an organisation team) with write access.

Because the output is plain static files, the site can later be moved to Codeberg Pages, GitLab Pages or an institutional server by changing only the deployment workflow and the DNS records.

## The logo

The mark is a protein sequence logo whose most conserved residue at each of four positions spells E-U-B-L (glutamate, selenocysteine, Asx and leucine are all valid IUPAC one-letter codes), coloured with the WebLogo "chemistry" scheme. It is a placeholder until an official logo exists, and it is generated by `tools/make_logo.py` (requires `pip install fonttools brotli`), which writes `layouts/_partials/logo-*.html` and `static/favicon.svg`.
